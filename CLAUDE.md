# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

There is no build, lint, or test tooling — the entire app is a single static HTML file.

- Preview: open `index.html` directly in a browser (`file://` works for everything, including Geolocation).
- To test under `http://` instead (e.g. for stricter permission/CORS behavior), serve the directory: `python3 -m http.server` and visit `http://localhost:8000/index.html`.

## Architecture

Everything — markup, CSS, inline SVG artwork, and JS — lives in the one `index.html` file (~430KB, most of it embedded OSM path data). No framework, no external JS libraries, no package manager. Google Fonts (`Jua`, `Gowun Dodum`, and `Gaegu` 700 for the zone signposts only — the user picked it from a side-by-side comparison as the cuter, storybook choice) are pulled via `<link>` tags. Signpost text is 68 units, the largest size that keeps 테크노밸리 등대 clear of the nail heads at the board ends.

**The map is drawn in a storybook style, but its geometry is real.** The big SVG (`#islandSvg`) draws Yuseong-gu's 13 행정동 as a single cohesive island. Only the decorative layer — trees, terrain shading, building icons, compass — is invented. The **outer boundary was traced from the real administrative boundary** (its bounding box has an aspect ratio of 0.589 against the real district's 0.593), and the **road network and waterways are real OSM geometry** projected onto it, not hand-drawn.

That makes a usable projection: linearly map real lon/lat onto the outline's bounding box (x from lon, y from **flipped** lat) and real coordinates land in the right place on the drawing. Every marker position was generated this way. Only the youth-facility pins are nudged apart by hand where they would stack; the dot layers sit at their projected spot, so positions are accurate to the neighborhood, not the street.

Two coordinate systems meet here, and conflating them is the easiest way to break the map. The **projection** is anchored to the island's bounding box and never changes. The **viewBox** is a window onto it that extends well past the island (currently `-157 -361 1914 3248`, 22% padding on each side) so neighbouring Daejeon shows as muted context instead of empty space. SVG geometry uses projection coordinates directly, but markers are HTML positioned with CSS percentages of `.map-wrap`, which tracks the *viewBox* — so `left% = (x - viewBoxX) / viewBoxWidth * 100`. Change the viewBox and every marker (~230) must be recomputed, along with the `aspect-ratio` on `.map-wrap` that mirrors it.

Roads come in two passes. The muted context band covers the whole viewBox and is drawn first, then the island fill paints over it, then the bright in-district roads go on top — so the context layer needs no clipping. Inside the district, roads are filtered to motorway/trunk/primary (drawn thick) and secondary/tertiary (thin); residential streets are deliberately excluded or the illustration disappears under them.

The five zone names are wooden signposts rather than flat labels, to suit the forest-adventure framing. Their positions are chosen by a small search that keeps each sign inside the island and clear of markers *while staying near its zone* — a zone name that drifts into the wrong neighbourhood is worse than one that overlaps a pin, so the search weights distance from the original spot heavily. The hard rule is that a **stake** never stands on a facility pin or the post office, checked at both a 375px phone and a 1280px desktop, because markers are CSS-pixel sized and cover different map areas at each width; facilities are never moved to make room, since their positions are real. Boards may still overlap markers. When they do, the search prefers to keep facility number badges (the lower half of the pin) visible. Around 온천 항구마을 no spot cleared every badge when the search ran (against the older 11-pin set). The user chose to raise the sign so the 장대 pin's badge (now 6) shows, accepting that the board half-covers the badges of 상담복지센터 and 미래교육지원센터 (now 3 and 4). They then hand-tuned it to `translate(708,1555) rotate(-10)` (about 10px lower on a phone, tilted 10° to the left). Keep that tilt; the other signs stay within ±3°. Both roads and waterways are Douglas-Peucker simplified at 3px. Waterways are clipped by the SVG `landClip` path rather than by coordinate, because 갑천 runs *along* the district boundary and a strict point-in-polygon test discards nearly all of it. Road and river name labels are positioned at the point on each road's principal axis (PCA) that sits furthest from any pin — don't hand-place them.

Beware the history here: pin `left`/`top` percentages were originally chosen *by eye* and were off by up to 20% of map width; they were regenerated from real coordinates on 2026-11-04. If you add new markers, derive their position the same way rather than eyeballing. And keep the distinction straight when the user says "실제 지도" — GPS accuracy vs. matching a reference image's visual style are two very different asks, and conflating them has cost several rounds in this project.

**Zoom:** the two SVG layers zoom by **narrowing their `viewBox`**, not by CSS transform. This matters: a `transform: scale()` on an SVG (especially with `will-change: transform`) lets the browser rasterise the layer once and stretch that bitmap, so the map blurs exactly like a zoomed photo — the first implementation did this and had to be replaced. Changing the viewBox re-renders the vector, so lines stay sharp at any scale. The HTML marker layer cannot follow a viewBox, so `applyTransform()` writes every marker's screen position itself — both halves run off one `{z, tx, ty, rot}` state, the SVG window via `vx = VX - tx·vw/width` and each marker via `px = tx + lx/100·width·z`. Three things deliberately do *not* grow with it. Markers are never scaled at all: `z` multiplies the *spacing* between them while each icon keeps its CSS pixel size, which is what pulls apart the pins that overlap at rest. Signposts get `scale(1/z)` appended after their `translate`, so the stake stays planted while the board keeps its size. Road strokes use `vector-effect="non-scaling-stroke"` with widths recomputed as `base × (mapWidth/1914) × z^0.4`; left to scale normally they swallow the map by 5×.

**Rotation** is a two-finger twist. It is applied *inside* the SVG as a transform on `#rotG` / `#rotGS` rather than to a container element: rotating the container turns the SVG box itself and leaves the frame corners empty, whereas rotating a group lets the oversized sea rect swing round and keep covering. The marker layer is not rotated either. Each marker's *position* is turned about the frame centre inside the same per-marker calculation (`hw + px·cos − py·sin`, `hh + px·sin + py·cos`), which carries it round with the world while leaving the icon itself upright.

Two traps here cost a round of broken builds, both silent — nothing throws, the map just stops working:

- **Never `setPointerCapture` on `pointerdown`.** Capture retargets the compatibility `click` to `#mapWrap`, so every pin, dot, chip and button underneath stops responding while the map still looks fine. Capture only after the pointer has moved past `DRAG_SLOP`.
- **Never scale the marker layer.** Markers are not transformed as a group at all: `applyTransform()` writes each one's final screen position (`markers[]` keeps its map position as a percentage). Scaling the layer and counter-scaling each marker back does hold their size, but the browser rasterises the shrunken icon and then magnifies it, so everything blurs as you zoom — and any `transition` on that counter-scale makes markers balloon and snap on every step. Placing them directly also means no counter-rotation is needed to keep them upright.

Because rotation sits outside pan and zoom, screen coordinates have to be converted back into the unrotated frame before use — `unrotate()` for a focal point, `unrotateDelta()` for a drag — or dragging goes sideways by exactly the rotation angle.

What stays upright and what turns is a deliberate split: signposts counter-rotate (`rotate(-rot)`) so they stay readable, while markers and the unread badge never rotate in the first place; the compass, the boat and everything else painted on the world turn with it, which is what finally makes the compass mean something. Road and river names turn with their road (they are road-aligned) and flip 180° when they would otherwise read upside down.

Panning works at every zoom level, with a 30%-of-frame margin beyond the content so the island can be dragged around even at rest; the sea rect is drawn far larger than the base viewBox so nothing empty shows at the edges. The zoom-out button doubles as 'back to the start' once the view has been panned, since at base zoom there is otherwise no way to recentre.

On touch, `touch-action` is `pan-y` at rest — vertical drags scroll the page, horizontal drags pan the map — and `none` once zoomed, when the map takes every direction. Without that split, a one-finger drag would trap the page scroll on a long phone page. Two-finger pinch works at any zoom.

The compass is drawn inside the map SVG, so it travels with the map and scrolls out of view when panned far. That is deliberate (it is map furniture, not a UI control) but it is the reason it can disappear; pin it to `#mapWrap` instead if that ever becomes a complaint.

**Alleys:** residential/unclassified/living_street/pedestrian ways (~52KB of path data) sit hidden under the main roads and fade in from z=2. `service` was excluded on purpose: it tripled the payload to 147KB and is mostly parking aisles, not the 골목길 people mean. The only transition left on a marker is the 0.12s hover lift on its inner glyph (`.pin .pin-glyph`), never on `.pin` itself — pan and zoom write `.pin`'s transform directly, so there is nothing to animate or wait out.

**Palette and the outside — a blue glass pane:** the ground was warm cream once — the most recognisable AI-design cliché. Outside the district was then painted as opaque open sea, with the neighbouring roads barely visible on top of it. That over-corrected: the user's intent is that 유성구 is an island *but still visibly connected to the rest of Daejeon*, as if the real map were seen through a tinted blue window.

So the outside is now layered: an opaque grey-green ground (`#BFCBCB`); a real-map layer `#ctxMap` drawn from OpenStreetMap (forest, built-up landuse, parks, water, rivers, rail — fetched via Overpass on 2026-11-17, projected with the same linear fit as the markers, features wholly inside the island dropped, forest simplified at 11px and small polygons removed to keep it ~92KB); the real surrounding road network in white; and a `--sea` glass rect at opacity .66 over both, with two faint diagonal glare bands, the wave pattern, and three neighbouring city names (세종 / 대전 시내 / 계룡) on top. The user asked for this explicitly as "실제 지도" under the glass — meaning real geography in this storybook style, not raster map tiles: tiles were offered and declined because they need the network on every load and blur when zoomed. The footer credits OpenStreetMap; keep that line if the layer stays. The island is painted after all of this, so it alone stays fully saturated. Three things were tried and rejected: making the sea itself semi-transparent lets the white page through and washes the blue out (the opaque ground underneath is what prevents that now); green ground under the glass mixes to teal and stops reading as a blue pane; very light ground leaves the white roads with nothing to contrast against. The context roads keep `vector-effect="non-scaling-stroke"` (1.3–3.4px) so they stay thin at every zoom instead of turning the glass into another landmass.

**Data model** (all in the `<script>` at the bottom of `index.html`):
- `FACILITIES` — the 6 youth facilities (청소년시설 chip), the only markers drawn as illustrated numbered pins with a legend row. `lat`/`lng` are geocoded from each facility's real address; `left`/`top` are derived from those via the outline projection above. 수련관·상담복지센터·미래교육지원센터 share one building (북유성대로 158), so their pins are fanned apart by hand or they stack exactly. 꿈드림 moved to 유성대로 798-1 (per the user's 2026-11 reference sheet), a few hundred metres from 장대, so its pin is fanned out to the north-east by hand; its `lat`/`lng` stay real. 장대's real spot (유성대로 780, per the sheet) sits right under the 온천 signboard, which would hide the whole pin, so its pin is drawn ~450m south at its old position (where the user tuned the sign to keep its badge visible) while `lat`/`lng` hold the real address for directions. Four facilities (수련관·구즉·꿈드림·장대) carry `addr`/`tel`/`hours` from the sheet; the facility modal and the place modal share `hoursTel()`. Until 2026-11-19 this list also held 엑스포과학공원, 국립중앙과학관 and three 다함께돌봄센터; they now live in `PLACES` (공공시설 / 돌봄시설).
- `PLACES` — 159 points for the 공원 / 도서관 / 공공시설 / 돌봄시설 chips, drawn as small coloured dots (`.place-dot`, colour from `PLACE_KIND`) and **prepended** to `#pinLayer` so they sit under the pins. Each has `k` (layer id), `sub` (modal tag: 근린공원, 도서관, 경찰, 소방, 지역아동센터 …), name, and where known `addr`/`tel`/`hours`. The list of parks, libraries, museums and care centres, with phone numbers and opening hours, comes from the user's reference workbook `유성구 지도 기초자료.xlsx` (kept outside the repo, compiled 2026-11). Police are the 유성구청 open dataset (data.go.kr 15154551, 2021; its 위도/경도 columns are swapped). Fire stations are named OSM `amenity=fire_station`. Coordinates come from, in order of trust: an exact OSM `addr:street`+`addr:housenumber` match; an OSM POI with the same name; walking `number × 10m` along the real OSM road from its west/south end (Korean road-address numbering, validated to ~30–120m on short roads, unreliable on long or curving ones, so it was used only for short roads); and, last, the road's centroid for short side streets. The sheet's parks have only 지번 addresses, which no keyless geocoder resolves (Nominatim returns the 동 centroid), so only the 93 of 173 parks whose name matches an OSM park are placed. The other 80, and 대정지역아동센터 (address not found), are deliberately left out rather than dropped at a 동 centre. Opening hours are shown with a "가기 전에 전화로 확인" note, since they change.
- `GUARDS` — 63 아동안전지킴이집 (child-safety shops) in Yuseong-gu. They come from the 경찰청 안전Dream 안전지도 Open API (`POST https://www.safe182.go.kr/api/lcm/safeMap.do`, `clArray=09`, paged 100 at a time, bbox-filtered, then kept only where the address contains 유성구 — that filter and a point-in-island test agreed on all 63). They were fetched once on 2026-11-17 and baked in, **not called at runtime**: the API needs an `esntlId` + `authKey` pair that would be public in a single HTML file, and it has a daily quota. The key belongs to the user and is kept outside the repo — never commit it. Positions use the same projection as everything else, with no overlap nudging. They are drawn as small rounded squares (`.place-dot.guard`) and **prepended** to `#pinLayer` so they sit beneath every other marker; at 63 they would otherwise bury the facility pins. Their chip (지킴이집) is off by default. They are wired into search and 내 주변 찾기. The police require the credit "자료 출처: 경찰청", which is in the sources footer.
- `NOTICES` — post-office bulletin items. Reassigned wholesale when the board server answers, so read it, don't cache it. Server notices carry a server-generated `id`, which is what the unread badge compares against.
- `LAYERS` — the chip row's state, in the order the user set on 2026-11-19: 공원 / 도서관 / 공공시설 / 돌봄시설 / 청소년시설 / 지킴이집. Only 청소년시설 is on by default. The 급식카드 chests and the 초·중·고 school layers were removed at the user's request on the same day (git history has them). `applyLayers()` is the single place that reflects state onto markers; chips persist to `localStorage`.
- `ICONS` / `REGION_BADGE` — lookup tables mapping a facility's `cat` (category) to pin artwork and a facility's `region` (1–5) to a badge color.

**Rendering pipeline:** JS builds every pin/dot/post/locate button at runtime from the arrays above and appends them into `#pinLayer` (percent-positioned, absolute, relative to `#mapWrap`). Icon markup comes from small SVG-string generator functions (`pinSvg`, `postSvg`, `locateSvg`) rather than static `<img>`/sprite assets.

**Modal system:** a single native `<dialog id="modal">` is reused for every detail view (facility info, place info via `openPlace`, 지킴이집 info, post notices, the "nearby facilities" list, and geolocation status/errors). Content is swapped by overwriting `#modalInner.innerHTML` and calling `showModal()`; check `modal.open` before calling it again to avoid `InvalidStateError` when updating content on an already-open dialog (e.g. loading → result).

**Geolocation — 내 위치 and "find nearby":** the top-right target button (`showMe`) puts the user on the map as **유성이**, the district's official character: a small coral dot at the real position with the character's face floating just above it. Then it pans the dot into view and starts `watchPosition`, so the face follows the user as they walk, but the view does not follow. The big 내 주변 보물 찾기 button and a tap on the face both open the ranked list instead. That list compares the user's position against everything in the enabled layers via haversine and caps it at 10; picking a row flashes that marker (`flashMarker`). The position never leaves the device. A position outside the viewBox hides the marker and says so, rather than pinning it to an edge. Until 2026-11-19 the user's position was deliberately never drawn; the user asked for it.

The face is the 「유성이 매뉴얼북」(2026) BS09 '기본' expression, lifted straight from the PDF's vector paths into the `yuseongiFace()` SVG string (~13KB). 유성구 has approved its use on this map (confirmed by the user, 2026-11-19). The manual forbids changing the character's shape, colour or proportions and asks that unavoidable changes go through the 유성구 managing department, so keep it as-is. Swap it only for another manual expression, never redraw or recolour it. The PDF lives outside the repo (the user's Downloads). `.me-marker` is appended to `#mapWrap` after `.sign-layer` rather than into `#pinLayer`, with z-index 8, because signposts (z 7) otherwise cover the face. It is therefore pushed into `markers` by hand right after the automatic registry. Map controls (zoom, locate, weather card) sit at z 9, above both: before this, a zoomed-in signpost could hide the − button and the weather card.

**Directions:** facility, place and 지킴이집 modals carry 길찾기 links that hand off to Kakao Map / Naver Map with the real `lat`/`lng` as destination (the user dropped Google Maps on 2026-11-22; Naver's `/p/directions` URL takes Web Mercator metres, converted in `routeLinks`). Routing is deliberately *not* computed in-page — the embedded network has no residential streets, so any route drawn here would diverge from the walk people actually take.

**Notices:** the post-office board is backed by a Cloudflare Worker, `worker/src/index.js`, deployed 2026-11-19 as `https://ys-youthmap-notices.ys-youthmap.workers.dev` with KV namespace `NOTICES`, all notices stored as one JSON array under key `notices`. The user asked to drop Google, so it replaced the earlier public Google Sheet via gviz plus an Apps Script writer, which is no longer used; that sheet's two notices were migrated. `NOTICE_API` at the top of the script is the only page config; empty or unreachable means the built-in sample notices. `GET /notices` is public. `POST /login`, `POST /notices`, `PUT /notices/:id` and `DELETE /notices/:id` need `Authorization: Basic base64(id:pw)`, checked server-side against Worker **secrets** `ADMIN_ID` / `ADMIN_PASSWORD`. Those values live only in Cloudflare: never write them into `index.html`, the HOWTO, this file or `wrangler.toml`. The repo and page are public, and the user has given the values in chat. `worker/.dev.vars` holds throwaway local test credentials and is gitignored. The Worker locks an IP out for 10 minutes after 10 failures, compares credentials via hashed constant-time comparison, and keeps the newest 100 notices. KV takes about a minute to propagate a write, so every write response carries the post-write list (`notices`), and the page uses it via `useNotices()` instead of re-reading. Other visitors see changes after about a minute. In the page, the admin logs in from a small link under the board. The Basic header is held in memory only (`adminAuth`); logout or closing the tab forgets it. Logged in, each notice gets 고치기/지우기 and a 새 소식 쓰기 button appears. Notice ids are server-generated; the unread badge compares them. Notice text is user-authored, so it is escaped before it reaches `innerHTML`; keep it that way. Non-coder instructions, including changing the password from the Cloudflare dashboard, are in `HOWTO-소식올리기.md`.

**`hidden` needs the global override.** Any element that declares its own `display` beats the UA's `[hidden]{display:none}`, so `el.hidden = true` silently does nothing — hence the `[hidden]{display:none !important}` rule near the top. This bit three separate things before it was found: the place card appeared empty on load, the unread badge never cleared after reading notices, and the weather card sat visible before its data arrived, so tapping it opened a modal full of `undefined` and `NaN`.

**Weather card:** bottom-left of the map, fed by two keyless CORS-friendly Open-Meteo endpoints (forecast + air-quality) for a fixed point near 유성구청 — deliberately not the user's position, so it renders without a location prompt. WMO weather codes map to one of six inline SVG icons; PM10/PM2.5 map to 환경부 grades.

Some devices cannot reach `open-meteo.com` at all — a user's phone could not even load the URL typed straight into the address bar, while the same page worked on desktop, so it is the domain being filtered (ad-block list or carrier), not the code. `wttr.in` is a keyless CORS-friendly fallback that covers temperature only; it reports WWO codes, which `wwoToWmo()` maps onto the WMO codes the icons expect. There is no keyless substitute for the dust reading, so that simply drops out on such networks. The fallback is a hedge, not a sequel: if open-meteo has not answered within 1.2s, `loadTemp()` starts `wttr.in` alongside it and takes whichever lands first (`Promise.any`). Waiting for the primary to fail first meant a blocked phone sat through two full timeouts before seeing a number. On a healthy network the primary answers first and the backup request is never sent.

Temperature and dust come from two different hosts and are fetched *and drawn* independently: bundling them meant one blocked host cost both readings, and `air-quality-api.open-meteo.com` is the likelier of the two to be filtered. Waiting on both before drawing (`Promise.allSettled`) was the other half of the same mistake — a temperature that arrived in 0.3s sat behind the dust request's timeout, so the card read `…` for seconds. Each reading now renders the moment it lands; the dust badge just joins later, and a missing one drops the badge.

`fetch` has no default timeout, so every request goes through `fetchJson()` with an `AbortController` (3s; 5s was long enough that a blocked request felt like a hang). A network that swallows the request instead of refusing it never settles the promise, and the card sat on its loading state forever with neither the retry nor the failure path ever running — that is what a blocked phone actually looks like, not a rejection.

The card always holds its place and shows its state (`…` while loading, `–° 다시` after three failed tries, tap to retry). Hiding it on failure was tried and is worse: the user cannot tell a blocked request from a feature that was never there, and the first version of this compounded it by being visible *before* the data arrived, so an early tap opened a modal of `undefined`. Never let `openWeather()` run without `weather.ok`.

To cut connection setup, the two open-meteo hosts are `preconnect`ed in the head. Starting the requests themselves from a head script was considered and deliberately not done: it would save a few hundred ms on phones but split the weather code between the top and bottom of the file, and the next maintainer cannot code. The render-as-it-lands, hedge and cache changes already cover the perceived delay.

**Weather on the map (날씨 연출):** added 2026-11-22. A `<canvas id="wxFx">` sits between the island SVG and `#pinLayer`, so markers and signposts stay readable above it. It is screen-space, so it falls "from the sky" regardless of zoom, pan or rotation. `setWeatherFx()` runs from `renderWeather('ok')` and maps `weather.icon` as follows: rain gives slanted streaks, a slight darkening and glass droplets sliding down (a nod to the blue-glass-pane outside); snow gives drifting flakes; storm gives heavier rain with a lightning flash every 4–9s. A 미세먼지 grade of 나쁨 or worse adds a yellow haze with drifting specks. Clear or cloudy draws nothing. It pauses when the map is off-screen (IntersectionObserver) or the tab is hidden, and draws a single still frame under prefers-reduced-motion. `?wx=rain|snow|storm|dust` previews an effect regardless of the real weather, though the weather card still shows the real reading. Rain was first drawn in white and was nearly invisible on the light map; it is now dark blue at 0.5 over a 13% darkening. Weather is re-fetched every 30 minutes while the page stays open (`refreshWeatherIfStale`, checked each minute and on tab re-show, skipped while hidden), so the card and the effect follow a change in the weather without a reload.

**Sources footer:** every data source the page shows is credited in the `<ul class="sources">` "정보 출처" list at the very bottom of the page — the user asked for this, and OpenStreetMap data requires attribution anyway. Adding a data source is not finished until it has a line there.

**Stamp collection (도장 모으기):** added 2026-11-22 as the "real treasure hunt" the map's name promised. `STAMP_SPOTS` holds 25 places: the 6 youth facilities, the 11 libraries and the 8 과학관·박물관 in `PLACES`. 공원 (93), 경찰·소방 and 돌봄시설 were left out on purpose as not "places kids go to visit". Every position the page receives goes through `checkStamps()`: `showMe`, `findNearby` and the `watchPosition` follow. Any unstamped spot within `STAMP_RADIUS` (100m) gets stamped with today's date, unless the fix is worse than `STAMP_MAX_ACCURACY` (150m). The radius is generous because some coordinates come from road-walk geocoding and can be tens of metres off. A new stamp opens a celebration modal (유성이 'BS09 눈 웃음' face, `yuseongiSmile()`, unmodified like the other face). If the user came from 내 주변 보물 찾기, the celebration replaces the nearby list. The 내 도장판 card under the big button shows progress and opens the board; tapping a cell turns its chip on and flashes the marker. Stamped markers get a red ring (dots) or a red ✓ corner (pins), and facility/place modals carry a `stampLine()`. Stamps are local only, so there is no cheating protection and nothing to protect: there is no prize.

**Persistence:** four `localStorage` keys. `yuseong_stamps` maps a stamp key (`f:<facility id>` or `p:<place name>`) to the date it was earned. `yuseong_weather` holds the last weather reading; one under an hour old is drawn immediately on load and then replaced by the fresh fetch, so a returning visitor never sees `…`. Older than that it is ignored, since the weather may well have changed. `yuseong_layers` holds the chip row's on/off state; `yuseong_seenNotices` holds the ids of notices already read, which drives the unread badge. It stores a list rather than a high-water date so that two notices posted on the same day both count as new.

**Mobile:** the page is phone-first in practice — the intended users are elementary students. Markers are sized in CSS pixels while the map scales with its container, so a pin that is 7% of the map on a desktop becomes 15% on a phone and swamps the island; the `max-width:560px` block shrinks every marker to compensate. Change marker sizes in both places or the phone layout silently regresses. There is no `<html>`/`<head>`/`<body>` wrapper, but the file does start with `<!DOCTYPE html>` plus charset and viewport meta — all three are required (without the doctype the page falls into Quirks Mode, without the viewport meta phones render it at desktop width).
